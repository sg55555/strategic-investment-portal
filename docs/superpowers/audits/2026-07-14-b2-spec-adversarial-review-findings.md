### IMP-5. spec が age の currentYear の source/TZ を未定義（now_ms 注入・UTC 導出が明記されず年境界パリティ穴が残る）
- **verdict**: CONFIRMED  / **finalSeverity**: important
- **根拠**: spec §43/§63 は age = Math.floor(currentYear − birthYear) を定めるが currentYear の導出源を一切定義していない。birthYear から月日を外したのは誕生日跨ぎ回避のみで、currentYear 自体の TZ/source は未規定。既存 facts パリティは now_ms を両実装に注入し UTC で年を取る idiom（deadlineBucket: getUTCFullYear / advice.py:212 datetime.fromtimestamp(now_ms/1000, tz=utc)、reserveMonthly も getUTCFullYear/Month）で厳密一致させている。age は §167 の top-level riskAssetPct/ageBucket と classes[].targetPct/driftPct（両モード・coarsen 対象 §171）を駆動するため、Dec31↔Jan1 の年境界で currentYear が JS/Py で 1 ずれると riskAssetPct/targetPct/driftPct/ageBucket と facts_hash が割れる。かつ client(money-rules.js=ブラウザ local TZ) と server(advice.py=UTC/Vercel) が別環境で recompute する構造ゆえ、素直な new Date().getFullYear()/datetime.now().year 実装だと年末年始に実ユーザーで client↔server パリティが割れ、同時刻 fixture では確実に捕捉できない。spec は now_ms 注入を deadlineBucket では厳密に定めながら age では沈黙しており §43 は「nowMs 境界パリティ問題を回避」と過剰に言い切っている点も不整合。指摘の fixture は nowIso でなく数値 nowMs キー（例 {"nowMs":0}）である点のみ用語が不正確だが、now を epoch で注入・case 固定という骨子は正しい。既存 idiom が強いため実装が誤る確率は下がるが、素直な実装が最も自然な経路であり穴は実在。
- **fix**: spec §3.1（§63 近傍）に currentYear の導出を固定明記する：注入済み now_ms から UTC 年で導く（JS: new Date(nowMs).getUTCFullYear() / Py: datetime.fromtimestamp(now_ms/1000, tz=timezone.utc).year）＝既存 deadlineBucket/reserveMonthly と同 idiom。§43 の「nowMs 境界パリティ問題を回避」は「birthYear の月日省略＋currentYear を注入 now_ms の UTC 年で導出」の両輪で回避、と正確化する。§173 の共有 fixture 計画に、nowMs を UTC 年末境界の epoch（例 2026-12-31T23:00Z 相当と 2027-01-01T00:30Z 相当の2値）に設定した age/riskAssetPct/ageBucket/driftPct の両言語一致ケースを追加し、client-local と server-UTC の乖離が起きないことを回帰化する（同時に §170 の符号付き drift・§171 の sign×bucket coarsen 一致も同 case でカバー）。

### IMP-6. spec §6 omits the required advice.py `_migrate` extension for birthYear/assetHoldings
- **verdict**: CONFIRMED  / **finalSeverity**: important
- **根拠**: The mechanism is real. Python mode_a_facts (advice.py:633) calls s = _migrate(raw_state) and reads every downstream field from s. _migrate (advice.py:252-266) is an allowlist rebuild that returns a fresh dict with only version/currency/monthlyExpense/bufferMonths/buckets/satelliteCapPct/reserves/goals/updatedAt — it deliberately drops all other keys (confirmed: cashSource/investmentSource/anchor are carried by JS migrate at money-rules.js:131-133 but intentionally absent from Python _migrate, because that Py subset only mirrors fields the facts pipeline consumes). The new facts.assetClasses need birthYear (age→targetPct) and assetHoldings (currentPct), and personal raw needs raw age. If _migrate is not extended, those keys are unseen → Python computes age=unset and currentPct=0, diverging from JS which has real values. The spec never states this: §2.2 line 49 names only the JS migrate (money-rules.js:115), §6 line 168 names only mode_a_facts (:630), §10 risk line 199 reads as JS defaultState/migrate. So the Python _migrate edit is a genuine unstated required step in a spec that claims decision-completeness (line 7). I downgrade severity from the claimed critical to important: §6 also mandates adding production/personal fixture parity cases, which is a built-in detector that goes red before merge (cannot silently ship), and the established pattern of mirroring migrate fields in both languages (goals/reserves/buckets) makes the fix likely — but the omission is still a real spec hole worth flagging.
- **fix**: In spec §6 (and cross-referenced from §2.2), add an explicit task: extend advice.py _migrate (:223) to coerce and include the new fields in its returned allowlist dict — birthYear (integer coerce), assetHoldings (via a Python mirror _normalize_asset_holdings following the _normalize_reserve template = 3 buckets × 7-key num coerce, unknown keys dropped), and optionally assetSource (enum coerce manual|ledger). State that _migrate is the Python entry that mode_a_facts reads from, so any facts.assetClasses field must be present on the migrated dict or the production/personal fixture parity will fail. Note the asymmetry: unlike JS migrate, Python _migrate only carries fields the facts pipeline consumes, so this is a required, non-optional addition (not automatically covered by "mode_a_facts に鏡像追加").
