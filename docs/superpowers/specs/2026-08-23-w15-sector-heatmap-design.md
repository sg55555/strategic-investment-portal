## 0. 背景・経緯

W1 のモック実物比較（2026-08-23）で案③セクターヒートマップは「実物は刺さった」が、**2つの未解決論点**を理由に次wave送りとなった。

1. **55業種の丸め方** — `industry` をそのまま group key にすると 1〜2社の業種ブロックが大量に出る。
2. **モバイル縦長 4758px** — 289銘柄ぶんの銘柄タイルを常時描くため。

本 wave はこの2点を設計で解いてから実装する。

### recon で判明した前提（実データ・2026-08-23）

- ユニバースは **289銘柄 / 54業種**（`data/universe.csv`）。Neon dump では 292銘柄 / 55業種（`情報通信・巨大投資` が1件多い）。
- **1〜3社の業種が23個**あり、かつ粒度が揃っていない（`電気機器・半導体` / `精密機器・半導体` / `電機・ITサービス` / `電機・インフラIT` が別業種として並ぶ）。
- ETF 23本が業種欄に混在（`国内ETF - TOPIX` 等）。
- `marketCap` は **list ペイロードに既に入っている**（`ticker_master.market_cap`）。ただし **JP=円 / US=ドルの混在**で、32件が 0（ETF 中心）。

## 1. 確定事項（本人決定・AskUserQuestion 2026-08-23）

| # | 論点 | 決定 |
|---|---|---|
| D1 | 面の主役 | **業種サマリ主体＋展開**（289銘柄のタイルを常時出さない） |
| D2 | 54業種→大分類の対応表の置き場所 | **rules 層の純関数**（DB / ETL / API 非接触） |
| D3 | 第1層のレイアウト | **案C 市場別2カラム**（日本株 / 米国株を別カラム） |
| D4 | 指標 | **3つ出す**（1日 / 5日 / 52週レンジ内位置） |
| D5 | 平均の既定 | **単純平均**（時価総額加重は切替として残す） |
| D6 | 表示 | **常時表示**（折りたたみ既定にしない） |
| D7 | 上昇社数バー | **残す**＋凡例に一行注記を足す |

### D5 の根拠（記録として残す）

母集合は本人が選んだ289銘柄で市場全体を代表していない。時価総額加重にすると「テクノロジー +0.83%」が実質 NVIDIA 1社の値になり、**指数のように見えて指数でない数字**が出る。単純平均は「選んだ銘柄群の平均」以上の意味を持たず、同じタイルの上昇社数バーとも見方が揃う。加えて時価総額 0 の32件が加重では黙って消える。加重は切替で担保する。

**案C を選んだ副次効果**：カラムが市場で分かれる＝各カラム内は単一通貨なので、案B で問題になった FX 換算（1ドル=150円の固定レート）が**不要になる**。加重は必ずカラム内で計算する（§5）。

## 3. 大分類（`sectorOf`）

### 3.1 写像

54業種（＋dump の `情報通信・巨大投資`）を **13大分類**へ落とす。`SECTOR_MAP` は `portal-price-rules.js` に literal で持つ。

```
テクノロジー   US-{テクノロジー,クラウド・SaaS,半導体・AI,SNS・AI,EC・クラウド,広告・クラウド,決済・フィンテック}
               電気機器・半導体 / 精密機器・半導体 / 電機・ITサービス / 電機・インフラIT /
               テクノロジー・家電 / 情報通信 / 情報通信・巨大投資
金融           US-{銀行・金融,保険,証券・資産運用} / 銀行・金融 / 保険 / 証券・金融サービス
ヘルスケア     US-医薬品・バイオ / 医薬品・バイオ
一般消費財     US-{小売・流通,飲食・外食,自動車,電気自動車・エネルギー,エンターテインメント}
               小売業 / 自動車・輸送機器 / 自動車部品・電装 / エンターテインメント
生活必需品     US-生活必需品 / 食品・飲料
資本財         US-資本財・防衛 / 重工・防衛 / 産業用ロボット / 空調・産業機器
素材           US-素材・化学 / 化学・素材 / 総合商社
エネルギー     US-エネルギー
公益           US-公益事業 / 電力・ガス
通信           US-通信
不動産         US-REIT・不動産 / 不動産
運輸           US-運輸・物流 / 運輸・インフラ
ETF            type=etf もしくは industry に "ETF" を含むもの（最優先で判定）
その他         未知業種のフォールバック
```

### 3.2 規約

- **シグネチャ**: `PortalPriceRules.sectorOf(industry, isEtf) -> string`
- **ETF 判定を最優先**（`isEtf === true` なら industry を見ない）。現在の既定フィルタ「株式のみ」では ETF 大分類は出ない。「すべて」「ETF」フィルタ時に出る。
- **未知業種は "その他"**（新銘柄追加でマップ漏れが起きても壊れない）。
- **並び順は固定**（`SECTOR_ORDER`）。社数順にすると、フィルタや検索で社数が変わるたびに並びが踊る。
- **その業種を含むカラムにだけタイルを出す**（社数0の大分類は描かない）。

## 4. 指標と色

### 4.1 指標（`METRICS`）

| key | ラベル | 元データ | 中央 | 振り切り | 表示 |
|---|---|---|---|---|---|
| `c1` | 1日 | `px.c1` | 0 | ±3% | 符号つき2桁 % |
| `c5` | 5日 | `px.c5` | 0 | ±6% | 符号つき2桁 % |
| `pos52` | 52週位置 | `px.pos52` | 50 | ±50 | 整数（0=安値 / 100=高値） |

`dh`（52週高値からの距離）は片側にしか振れないため**発散スケールに載せない**（`pos52` を採る）。

### 4.2 色

- **2色＋中立グレーの5段**。中立はパネルの地色に寄せた `rgb(35,46,56)` ＝「動いていない業種は色がつかない」。
- 上昇/高値側 `rgb(0,200,110)` / 下落/安値側 `rgb(255,70,105)`（W1 の値動き列と同系）。
- 段は `|正規化値|` の 0.20 / 0.42 / 0.62 / 0.82 / 1.0 で切る。`|d| < 0.06` は中立。
- **タイルに数値を直書きする**（色だけに情報を載せない）。塗りが濃い上位2段は**文字色を黒に切り替える**（白文字だとコントラストが落ちるため）。
- **凡例は常設**：下落←→上昇のスウォッチ列＋現在指標の注記（例「前日比（±3%で振り切り）」）＋**上昇社数バーの説明を一行**（D7）。

---

## 5. 集計

- **母集合は表と同じ**（`lastPortalList`＝検索・スクリーニング・セクターフィルタ適用後）。W1 のストリップと同一の値を使う。
- `px` を持たない銘柄は集計から除く（社数には含める）。
- **単純平均**（既定）＝ 対象銘柄の指標値の算術平均。
- **時価総額加重**（切替）＝ `Σ(v_i × cap_i) / Σ cap_i`。**必ず市場カラム内で計算する**（JP カラムは円、US カラムはドルで閉じる＝通貨混在を作らない）。カラム内 `Σcap == 0` なら単純平均へフォールバック。
- **上昇社数バー**＝ `up / (up + down)`。中央（`pos52` なら50）超を up、未満を down、同値はどちらにも数えない。

## 6. レイアウト

### 6.1 第1層（案C）

- パネル見出し：`市場の温度感　<指標ラベル>　/　市場ごとに大分類を並べる`
- 2カラム（`日本株` / `米国株`）。各カラムの見出しに**その市場の as-of 日付**を出す（`market_asof` 再利用）。
- カラム内は大分類タイルのグリッド（`repeat(auto-fill, minmax(124px, 1fr))`）。タイルは `<button>`（キーボード到達可能）。
- タイル内容：大分類名 / 値（mono・太字）/ `N社` ＋上昇社数バー。

### 6.2 第2層（展開）

- 大分類タイルのクリックで、**両カラムの下**に全幅の展開パネルを出す（1つだけ＝アコーディオン・再クリックで閉じる）。
- 展開の中身：その大分類の銘柄を**小分類（元の54業種）で束ね**、各束は指標の降順。銘柄タイルは短縮名＋値（日本株は社名先頭4文字・米国株はティッカー）。
- 銘柄タイル → 詳細ビュー（`navigateToDetail`）。小分類見出し → **表をその業種に絞り込み**（既存 `setSectorFilter`）。
- 展開状態は**保存しない**（毎回閉じた状態で開始）。

### 6.3 モバイル（390px）

- `.w15-cols` を1カラムにして日本株→米国株の縦積み。タイルは `minmax(104px, 1fr)`。
- 実測（モック・headless）：閉じた状態でページ全体 **+796px**、展開時 +1800px。W1 で見送った案③は **4758px** だった。

## 7. 劣化・鮮度

- **`px_error` の日はパネルごと非表示**（W1 と同じ「価格が取れないだけで一覧を失わない」原則）。エラー文言も出さない（ストリップ側が既に劣化表示を担っている）。
- 母集合0件のときも非表示（表側が「該当する企業が見つかりません」を出す）。
- **銘柄ごとに最終終値日が違う**（JP 8/20・US 8/21・EA だけ 8/10 という実例がある）。案Cは市場カラムに分かれるため、**カラム見出しの as-of で市場単位の鮮度を正直に示す**。銘柄単位の stale 除外は行わない（サマリの母集合を勝手に減らさない）。

## 8. 純関数レイヤ（`portal-price-rules.js` への追加）

既存の UMD に以下を追加する。**DOM 非依存**・描画は `index.html` 側。

| 名前 | 役割 |
|---|---|
| `SECTOR_MAP` / `SECTOR_ORDER` | 54業種→13大分類の写像と固定並び順 |
| `sectorOf(industry, isEtf)` | 大分類キーを返す（ETF 最優先・未知は "その他"） |
| `HEAT_METRICS` | 指標定義（中央・振り切り・桁・符号・注記） |
| `heatValue(px, metric)` | 指標値の取り出し（欠損は null） |
| `heatAggregate(items, metric, weight)` | `{v, n, up, down, cap}` を返す（加重は呼び出し側がカラム単位で渡す） |
| `heatStep(v, metric)` | 色段 `{i, up}`（中立は `i < 0`）＝塗りと文字色の唯一の根拠 |
| `groupBySector(items, metric, weight)` | 大分類ごとの集計配列（`SECTOR_ORDER` 順・空の大分類は落とす） |

**W1 の方針を踏襲**：数値計算はここに集約し、`index.html` 側は整形と描画だけ。JS↔Py 鏡像パリティは**新設しない**（サーバ側に同じ計算を置かないため）。

## 9. 規制・文言

- **ヒートマップパネルには免責文を置かない**（決定）。W1 で「免責文が上下100pxで逐語重複」を実際に踏んでいるため、**直下のストリップ末尾にある既存の免責文1つが両パネルをカバーする**構成にする。ヒートマップが見える状況ではストリップは必ず通常状態＝免責文も必ず出る（`px_error`・0件ではヒートマップ自身が消えるため、免責が無い状態でヒートマップだけが残ることはない）。
- 受入項目：**画面上に免責文が1つだけであること**を実 DOM で確認する。
- 指示的文言（買い/売り/推奨/狙い目）は使わない。

## 10. 性能

- 計算は 292件 × 1パスの集計のみ。`filterAndRenderPortal` 1回あたりの追加コストは無視できる（実測で体感差なし）。
- **描画は表の窓化（Plan 2）と独立**。ヒートマップは母集合全件を集計するが、DOM は大分類タイル最大 22枚（＋展開時に最大 75枚程度）。
- payload 増加ゼロ（既存フィールドのみ使用）。

## 11. 検証計画

### node テスト（`tests/`）

1. `sectorOf` の**54業種＋dumpの1件＝全件の写像を固定**（表を書き換えたらテストが落ちる）。

## 12. リスク・申し送り

- **`SECTOR_MAP` は手作りの表**＝ユニバース拡張時にマップ漏れが起きうる。壊れないよう「その他」へ落とすが、**"その他" が育っていないかを見る導線がない**。テストに「"その他" に落ちる業種が現ユニバースに存在しないこと」を入れて検知する。
- 大分類は**このパネル専用**で、ランキング/散布図のセクター帯（38分類ベース）とは別体系。将来統合するなら DB の `sector` 列化（今回の非採用案B）に進む判断が要る。
- 案B（時価総額 treemap）はモックに残す。「市場の重み」を見たい要望が出たら第2の切替として復活できる（ただし FX レートの出所を決める必要がある）。
